# Atlas v0.3.7-beta.4.2.4 — confirmed Journey history and canvas recovery

This is an **unmerged Foundry v14 GM test build**. Back up the World first. Test with the active GM and a second non-GM client where possible.

1. **Rest-triggered Canvas rebuild:** Start a route longer than eight travel hours with Atlas World time enabled and a calendar/weather module that redraws the canvas at a Long Rest or Overnight Camp. When the GM approves the rest, Atlas must finish the World-clock write and checkpoint the approved break before an automatic restart can begin. The old movement loop must end; the resumed leg starts at the token's current position with the **same Journal**. Check no duplicate rest, World-time credit, or token movement. If either the clock write or checkpoint fails, Atlas must **not** restart automatically. Use manual recovery instead.
2. **Interrupted Journal honesty:** Interrupt a route halfway through a road, then open **Atlas Journey Summary** in **Atlas Navigation Logs**. The current leg's listed directions must stop at confirmed progress. Its planned **Distance** and **Moving time** remain visible as route metadata, and the underlying `guidedJourney` flag still has the full original directions for safe recovery. The Journal's confirmed moving and break totals must agree with actual token movement and approved rests. Repeat after recovering a saved leg.
3. **Journal write cadence:** With Atlas Debug **Verbose**, travel a longer route. Atlas should checkpoint the Journal after each fifth confirmed native movement segment, and immediately at a daily-limit decision, confirmed rest, Pause, End, interruption, or completion. Avoid assuming an in-progress Journal has every small native stretch recorded before the next checkpoint; an actual canvas teardown should flush the confirmed remainder.
4. **GM controls and two-client safety:** Verify Pause/Resume, End Journey, a rest-choice pause, Scene switch, road revision change, and active-GM changes never trigger unauthorized continuation. The assigned explorer token must still follow native Foundry movement permissions and Region Behaviors. Player Journal access should remain disabled by default; player fog, roads, checkpoints, weather, and other Scene effects should behave as before.
5. **Flicker observation:** Compare the remaining token/terrain flicker with Atlas Debug **Trace**. Record whether a flash happens at a native movement boundary, a Journal checkpoint, a fog-cell discovery write, or a full Foundry/third-party canvas redraw. This build reduces routine Journal writes; it does **not** block Foundry canvas rebuilds or patch private rendering state. A flicker fix remains **provisional**, pending video and live observation.
