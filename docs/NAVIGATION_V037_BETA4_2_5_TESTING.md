# Atlas v0.3.7-beta.4.2.5 — Journey naming and party departure

This is a **GM-only Foundry v14 draft test build** stacked on beta.4.2.4. Back up your World and leave the PR unmerged until owner acceptance.

1. **New Journey name:** In Paedor, with authored checkpoints close to the start and destination, start a new guided trip. Confirm the Journal Entry name follows **`[Foundry in-world date/time] — [nearest starting checkpoint] to [nearest destination checkpoint]`**, using the World calendar shown in Foundry. The native timestamp is captured **before** Atlas advances the World clock. The managed Summary heading should also identify the route and current status.
2. **In-world time log:** Confirm the managed Journey Summary records **Departed (World time)** at travel start; each Short Rest, Long Rest and Overnight Camp shows its recorded start and end World times; and **Arrived (World time)** appears only after confirmed completion. With the World-time setting enabled, an 8h rest should move the displayed end timestamp by 8h, and a subsequent movement should move the arrival timestamp by only its confirmed travel time. Continue March can show its GM decision time without inventing downtime. With World-time advancement disabled, displayed times remain at the actual unchanged Foundry clock value.
3. **Stable identity on recovery:** Take a Long Rest or trigger a permitted canvas rebuild. The original Journey Journal **must not be renamed or duplicated** when recovery opens a new leg, even if the campaign calendar advances into a new day. Saved departure and break timestamps must remain unchanged, and an eventual arrival time should be appended to the same record. Existing older Journals must retain their names and flags.
4. **Missing information:** If no checkpoints are available, use **Map Point A to Map Point B**, not a fabricated settlement. If the World calendar is temporarily unavailable, the title uses **Atlas Journey** without inventing a real-world date. These fallbacks do not interfere with guided movement.
5. **Default departure:** Open Navigation on a Scene with a valid manually assigned Atlas explorer token. **Party token location** must be selected immediately, its current center must define Point A, and a normal map click should select Point B. **New Route** should keep the party departure. Switching to **Map point A** must still work explicitly.
6. **No assigned/usable token:** On a Scene without a configured explorer, or when its placed TokenDocument cannot be used, Navigation should default to **Map point A** and remain usable. Do not auto-assign or move a token.
7. **Regression smoke test:** Confirm existing roads/checkpoints, native Regions, player fog/weather, Journey Journal permissions, Pause/Resume/End, rest and World-time accounting, and two-client display still work. The intermittent flicker and external canvas redraw/closure remain **known deferred issues**; no native canvas rebuild suppression is introduced in this build.
