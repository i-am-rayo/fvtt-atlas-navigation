# v0.3.9-beta.4 — Automatic discovery and committed break banners

**Draft for owner GM + non-GM Foundry v14 acceptance.** Builds on the owner's confirmed beta.3/3.1 visuals and queue. November 6 live report: an automatic unknown→Seen/Visited toll/bridge checkpoint produced no discovery banner; clicking **Pause Journey** and **Long Rest** also produced no banner. These are different causes, not evidence that the five-second renderer discarded events.

## Investigation and scope

1. `atlas-token-exploration.js` calculated nearby checkpoints and persisted automatic discovery through `saveAutomaticCheckpointVisits`, but ignored the list of newly saved IDs. No producer called the banner runtime. After a successful Scene flag write, beta.4 verifies the live Scene flag still records an **unknown→visited**, **Automatic** discovery and queues `checkpoint.discovered` for each newly committed ID. GM sees the real name; players see only **a new location**. Previously seen/lore/manual checkpoints, unchanged passes, save failures, and hidden candidates never announce.
2. Roads use a different ownership contract: **Show to players** is a GM-authored `Road.playerVisible` flag, not proximity exploration. A **false→true** flag change through Road Settings or the quick visibility toggle, after the revision-checked Scene write, requests `road.discovered`. Renames and edits of already-visible roads do not. This is a *GM reveal*, not automatic road discovery while traveling; those are separate future requirements.
3. `saveJourneyCheckpoint` requested `journey.paused` without the required `manualPause:true` eligibility proof. Beta.4 supplies that proof **only** from the explicit `pausing` phase after Journal save, and prioritizes this deliberate pause over a coincident checkpoint-arrival branch. Canvas interruption, day-limit choice and preview do not become manual pauses.
4. An approved Long Rest was already recorded in the Journey Journal with World time, but neither `break.started` nor `break.ended` was emitted. Beta.4 now checks the *new* Journal rest event (`long`, `short`, `overnight`, positive duration), verified against the saved Journal. Both visual phases are queued **after the entire rest commit**—they do **not** perform a second rest or pretend a clock write is still pending. Re-saving an unchanged Journal, choosing Continue, or a failed write cannot produce them. Underway passenger rests are eligible only once actually recorded, not when requested.
5. `atlasAnnouncementPulse` remains a single public-safe World setting pointer. Writers now serialize updates to reduce rapid overwrite/racing of online clients; client-side renderers still show one banner for five seconds. Like before, the pulse is *not* durable event history or an offline replay channel. Network-disconnected clients may miss events; an active player client should receive each broadcast.
6. The GM-only Module Settings **Atlas — Announcement Banner Samples** now includes **Recent banner decisions**: event name, local checkpoint/road name, old→new status, method and queued/rejected result. Click **Refresh discovery diagnostics** to update the list (latest 12 from the browser's bounded last-32 history). The logs do not persist in Scene/Journal/World settings and are not sent to players. Under **Atlas Debug — Console Logging Level → Verbose**, filter browser console for `[fvtt-atlas-navigation][announcement]`; this includes rejected transition receipts and player-safe receipt status. Banner delivery remains display-only/best-effort.

## Owner acceptance matrix (GM + a separate non-GM player)

1. Install the beta.4 branch manifest; verify version `0.3.9-beta.4` on both clients. GM selects **Atlas Debug → Verbose**, opens the banner sample menu after each trigger, clicks **Refresh discovery diagnostics**.
2. At a Scene with Atlas manual fog and a manually assigned explorer, set two new nearby bridge/toll checkpoints to **Discovery: Automatic** and **Unknown**, then travel past them using speed `4`. Verify Scene knowledge changes to **Seen / Visited** and **one discovery banner per newly visited checkpoint** on both clients. GM may see their names, player must see generic text only. Expected GM diagnostics: `Unknown → Seen / Visited; Automatic proximity; GM banner queued; public pulse scheduled`. If their distances are close, each waits five seconds on each client. Travel speed should not alter authorization or World-time calculations.
3. Return along the same road; no duplicate discoveries. Set another checkpoint to **GM** or **Known through Lore** and pass it; no automatic discovery banner. Repeat after a Canvas redraw to prove read-only initialization does not replay banners.
4. In Road Settings enable **Show to players** for a previously hidden road; verify one Road Discovered banner and `hidden → shown` diagnostic. Rename the road while still shown: no new banner. Also test the Road quick visibility toggle. Disabling visibility must not issue a discovery banner. No native Regions, surface costs, topology, or other road data should change.
5. During an actual moving Journey click **Pause Journey** and wait for the next confirmed native movement boundary and Journal checkpoint. **Journey Paused** should display once. No banner merely from the click if the Journal write fails, and no automatic pause from canvas teardown.
6. While paused, click **Long Rest**. Confirm the Journal has exactly one new long-rest event and the expected 8h (or World rules' configured length) of downtime, with token stationary. Only after the commit, **Break Started → Break Ended** appear sequentially, five seconds each, on both clients. A failed Journal save must show neither. Try the daily-rest prompt/Short Rest for appropriate alternate event types. Confirm no Actor rest, resource, currency or duplicate World-time change.
7. Queue multiple checkpoint discoveries near a rest/arrival; verify the queue order and that each banner fades cleanly. With player relog/reconnect, ensure old pulses don't replay. Inspect console for Atlas errors separately from third-party warnings.

## Boundaries and deferred work

- No new Scene, Journey Journal, World settings, native Token, Actor, Fog or Region schema. No migrations, automatic Actor rests, purchases, route changes, or Canvas rebuild suppression.
- Road proximity discovery while walking **without** GM Show to players is not implemented. The current road event reflects explicit GM visibility.
- Customizing the five-second lifetime, persistent event inbox/history, canvas animation pacing, and richer GM event subscriptions remain separate work. Animation speed is already configurable under **Transportation Presets → Journey & playback**; it changes visual time only.
- Automated test success is **not** Foundry v14 owner acceptance. Keep this PR draft until both GM and player verify the matrix.
