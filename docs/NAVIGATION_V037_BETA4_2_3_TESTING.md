# Atlas v0.3.7-beta.4.2.3 — guided travel recovery

This is a **GM-only test build**. Keep a backup of your World. Avoid merging until the owner completes these checks on Foundry v14.

1. **Journal folder:** Start a new journey. Verify that its Journal Entry is inside **Atlas Navigation Logs** and subsequent journeys reuse that folder. Existing Journals elsewhere are left untouched. Open the Journal and confirm Atlas manages only its Summary page; separate personal note pages are untouched.
2. **Arrival percentage:** Complete a normal route. The token must reach its destination, the progress label must stay at **100%**, and the Journal must be marked **Completed**. Verify the footer returns to Travel Route once the active journey is finished.
3. **Automatic canvas recovery:** Start a long route with a functioning World clock. At a calendar/weather transition that makes Foundry rebuild the canvas, the old route should stop, checkpoint, and automatically continue on the **same Scene** from the live token position. The Journal should gain a new leg without a second Journal Entry. Previously credited World time must not advance twice. A brief warning that Atlas is attempting safe continuation is expected.
4. **Safety boundaries:** Pause manually, choose a rest, press End Journey, and switch Scenes while moving. None of these should cause uncontrolled automatic movement. If the Scene or assigned party token changes, or the road graph revision changes, auto-continuation should stop. The original Journal must remain available for the existing GM review/recovery flow where eligible. After six consecutive canvas rebuilds during one journey, Atlas stops trying automatically.
5. **Daily limits after recovery:** Travel eight hours, select Long Rest, then continue past the next daily boundary. A restored journey should preserve that day's travel count and forced-march allowance. The Directions event cards and Journal should show **on this leg** and **traveled today** separately. No additional rest or forced-march credit is invented.
6. **Token flicker:** Compare with Hexplorer using the same token, Scene, and fog state. Atlas still uses separate short native TokenDocument moves to retain reliable pause/end controls. Hexplorer listens to normal token movement and updates fog independently; it does not provide a drop-in guided-travel movement loop. Record whether flicker coincides with a movement-chunk boundary, a new Atlas fog-cell save, or a third-party Scene/weather redraw using Atlas Debug **Trace**. Do not suppress native movement permissions, Token constraints or Region Behaviors.

To install this draft: use the Manifest URL for `test/v0.3.7-beta.4.2.3` from the published test branch. If automatic recovery cannot safely verify the Scene, token, road revision, active GM or finalized Journal write, Atlas leaves the trip recoverable manually; it must never replay completed travel or World time.
