# v0.2.25.4.1 — Player Overlay Guard (Test Hotfix)

Stacked on v0.2.25.4, in a new draft PR. Not merged.

## Owner report

After setting Orc Bridge to **Known through Lore**, the player's road and checkpoint overlay disappeared. A console log showed unrelated browser READ-buffer performance warnings and a Taskbar module's deprecated `JournalPageSheet` access; neither log alone proves the Atlas render error.

## Fix

- A terrain-mask renderer error can no longer abort the subsequent player road/checkpoint draw after its graphics buffer was cleared.
- Render the optional Scene-background reveal copy **hidden until a valid Pixi mask has been drawn**.
- Keep Atlas road/checkpoint graphics above the temporary background-copy layer in the interface display list.
- Log a single identifiable warning if terrain mask preparation fails; skip only the optional terrain reveal and preserve existing roads/checkpoints.
- Native Foundry FogExploration data remains untouched. All checkpoint discovery states and reveal-radius settings are preserved.

## Manual acceptance (ordinary player account)

1. Update module using the branch-specific manifest below, refresh both GM and player clients.
2. Return Orc Bridge to **Undiscovered**; confirm previously visible roads/checkpoints remain intact.
3. Set **Known through Lore**; confirm roads and other checkpoint markers **still display**.
4. Verify whether terrain-background circle appears; if not, copy the console warning beginning `[fvtt-atlas-navigation] Optional terrain reveal unavailable` including its actual error/stack.
5. Try radius 3, then 0, then Undiscovered. Native exploration and other checkpoint visibility must not change.
6. Repeat in a different Scene and after page reload.
7. Do not merge until player-side v14/Pixi behavior is confirmed.
